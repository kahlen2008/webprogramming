05 · Caching

Loading Strategy

Browser caching stores a copy of resources (CSS, JS, images) locally. When a user revisits your site, the browser loads those resources from the local cache instead of downloading them again. This makes repeat visits dramatically faster — often instantaneous.

HTTP Headers & Cache Busting 
/* Server response headers — set by server (Apache/Nginx/Node) */

// Cache for 1 year — for versioned files (CSS/JS with hash)
Cache-Control: public, max-age=31536000, immutable

// Cache for 1 hour — for frequently updated content
Cache-Control: public, max-age=3600

// No cache — for HTML pages that must always be fresh
Cache-Control: no-store

/* Cache Busting — add version hash to filenames */
/* When updated, hash changes → new URL → downloads fresh */
<link rel="stylesheet" href="styles.a3f9c2b1.css">
<script src="app.d8e4f2a9.js" defer></script>

/* Build tools (Vite, webpack) add these hashes automatically */

Key Points
  • Browser caching stores resources locally so repeat visits become virtually instantaneous.
  • Use Cache-Control: public, max-age=31536000, immutable for versioned static assets (CSS, JS, images).
  • Cache Busting (unique build hashes like app.d8e4f2a9.js) ensures users immediately receive updates without stale cache bugs.
  • HTML documents should use Cache-Control: no-store or short TTLs so users always receive latest markup.
