04 · JavaScript Loading Strategy

Loading Strategy

By default, when the browser encounters a <script> tag, it stops parsing HTML, downloads the script, executes it, then continues. This "render-blocking" behavior is the most common cause of slow page loads. Two attributes fix this: defer and async.

HTML — Script loading attributes 
<!-- ❌ Default — blocks HTML parsing (render-blocking) -->
<script src="app.js"></script>

<!-- ✅ defer — fetches in background, runs AFTER HTML is fully parsed -->
<!-- Preserves order: script1 runs before script2 -->
<!-- Best choice for most scripts that need the DOM -->
<script src="app.js" defer></script>

<!-- async — fetches in background, runs as soon as downloaded -->
<!-- Order NOT guaranteed — good for independent scripts (analytics) -->
<script src="analytics.js" async></script>

<!-- Always put scripts in <head> when using defer/async -->
<head>
  <script src="app.js" defer></script>
  <script src="analytics.js" async></script>
</head>

Key Points
  • Default <script> in <head> blocks HTML parsing — major performance bottleneck.
  • defer — downloads in background, executes after DOM is ready, preserves order. Best for most scripts that interact with the DOM.
  • async — downloads in background, executes as soon as ready, order not guaranteed. Ideal for analytics, trackers, and independent beacons.
  • Both defer and async are only meaningful for external scripts with a src attribute.
  • Use defer as the default standard. Use async only for scripts that don't depend on other scripts or the DOM.
