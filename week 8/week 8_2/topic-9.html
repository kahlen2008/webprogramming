ARIA & Accessibility

Accessible Error States

When JavaScript inserts error messages dynamically into the DOM, screen readers do not automatically detect them. ARIA attributes (aria-describedby, aria-invalid, and aria-live="polite") announce dynamic validation states to assistive technologies.

HTML + JavaScript 
<!-- 1. Link error span to input -->
<div>
  <label for="email">Email</label>
  <input type="email" id="email"
         aria-describedby="email-error"
         aria-required="true">
  <span id="email-error" role="alert" aria-live="polite"></span>
</div>

// 2. Toggle aria-invalid with JS
function showError(input, errorEl, msg) {
  errorEl.textContent = msg;
  input.setAttribute('aria-invalid', 'true');
}

function clearError(input, errorEl) {
  errorEl.textContent = '';
  input.setAttribute('aria-invalid', 'false');
}
Live Accessibility Inspector Try typing
<input id="email" aria-describedby="email-error" aria-invalid="false">
<span id="email-error" role="alert" aria-live="polite">""</span>
🔊
Screen Reader Announcement:
"Email, edit text, required."
Key Points
  • aria-describedby="error-id" connects the error container to the input so screen readers read the error when focusing the field.
  • aria-invalid="true" informs assistive technology that the entered value currently fails validation.
  • aria-live="polite" (or role="alert") prompts the screen reader to speak the new error message without interrupting the user mid-sentence.
  • Set aria-invalid="false" or remove it when the field passes validation.
