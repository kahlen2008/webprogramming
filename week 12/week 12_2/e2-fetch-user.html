Fetch a User from an API

Task Specification: Use https://jsonplaceholder.typicode.com/users/1 to fetch a user and display their name and email. Show "Loading…" while fetching and handle errors.

The component fetched user 1 once when the page loaded.
UserProfile.jsx React + Vite 
import { useState, useEffect } from 'react';

function UserProfile() {
  const [user, setUser]       = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError]     = useState(null);

  useEffect(() => {
    async function fetchUser() {
      try {
        const res  = await fetch('https://jsonplaceholder.typicode.com/users/1');
        if (!res.ok) throw new Error('Failed to fetch');
        const data = await res.json();
        setUser(data);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    }
    fetchUser();
  }, []); // empty array — run once on mount

  if (loading) return <p>Loading…</p>;
  if (error)   return <p>Error: {error}</p>;

  return (
    <div>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  );
}

export default UserProfile;

Key Takeaways

  • Empty dependency array []: the effect runs once after the first render (on mount), so the user is fetched once, not on every re-render.
  • Async function inside the effect: the effect callback itself can't be async (it must return nothing or a cleanup function), so we define fetchUser inside it and call it straight away.
  • Check res.ok: fetch only rejects on network failure. A 404 still resolves, so we throw ourselves to send it to catch. Tick Use a bad URL to see this.
  • finally + early returns: setLoading(false) runs after success or failure, and the if (loading) / if (error) returns mean user.name is only read once user is set.
