GitHub User Lookup

Task Specification: Build a component that:
  1. Has an <input> for a GitHub username.
  2. On Search button click (or a 500ms debounce), fetches from https://api.github.com/users/{username}.
  3. Displays avatar, name, bio, followers and public_repos.
  4. Shows a loading indicator while fetching.
  5. Shows an error message when the user is not found (404).
  6. BONUS: aborts the previous request when the username changes.

GitHubUserLookup.jsx React + Vite 
import { useState, useEffect } from 'react';

function GitHubUserLookup() {
  const [username, setUsername] = useState(''); // what's typed in the input
  const [query, setQuery] = useState('');       // what we actually fetch
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  // 2a. Debounce: copy username into query 500ms after typing stops
  useEffect(() => {
    const timer = setTimeout(() => setQuery(username.trim()), 500);
    return () => clearTimeout(timer); // typing again cancels the old timer
  }, [username]);

  // 2b. Fetch whenever query changes
  useEffect(() => {
    if (!query) {
      setUser(null);
      setError(null);
      setLoading(false);
      return;
    }

    const controller = new AbortController(); // 6. BONUS

    async function fetchUser() {
      setLoading(true); // 4. loading indicator
      setError(null);
      setUser(null);
      try {
        const res = await fetch(
          `https://api.github.com/users/${encodeURIComponent(query)}`,
          { signal: controller.signal }
        );
        if (res.status === 404) throw new Error(`User "${query}" not found`); // 5.
        if (res.status === 403) throw new Error('Rate limit reached, try again later');
        if (!res.ok) throw new Error(`Request failed (${res.status})`);

        const data = await res.json();
        setUser(data);
        setLoading(false);
      } catch (err) {
        if (err.name === 'AbortError') return; // replaced by a newer request
        setError(err.message);
        setLoading(false);
      }
    }

    fetchUser();
    return () => controller.abort(); // cleanup: cancel the old request
  }, [query]);

  // Search button: skip the 500ms wait
  const handleSubmit = (e) => {
    e.preventDefault();
    setQuery(username.trim());
  };

  return (
    <div className="github-lookup">
      <form onSubmit={handleSubmit}>
        <input
          value={username}
          onChange={(e) => setUsername(e.target.value)}
          placeholder="GitHub username"
        />
        <button type="submit">Search</button>
      </form>

      {loading && <p>Loading...</p>}
      {error && <p className="error">{error}</p>}

      {user && (
        <div className="user-card">
          <img src={user.avatar_url} alt={user.login} width="100" />
          <h2>{user.name || user.login}</h2>
          <a href={user.html_url} target="_blank" rel="noreferrer">@{user.login}</a>
          <p>{user.bio || 'No bio'}</p>
          <p>Followers: {user.followers}</p>
          <p>Public repos: {user.public_repos}</p>
        </div>
      )}
    </div>
  );
}

export default GitHubUserLookup;

Key Takeaways

  • Two pieces of state, two effects: username changes on every keystroke, but query only changes after the debounce or a Search click. The fetch effect depends on query, so typing doesn't send a request per letter.
  • Debounce = timer + cleanup: each keystroke re-runs the effect, and the cleanup clearTimeout cancels the previous timer. Only the timer that survives 500ms of quiet calls setQuery.
  • fetch doesn't throw on 404: it only rejects on network failure. Check res.status / res.ok yourself and throw, so the 404 lands in catch and becomes the error message.
  • AbortController stops stale results: when query changes, React runs the old effect's cleanup, which calls controller.abort(). The old fetch rejects with AbortError, which we ignore, so a slow old response can't overwrite the new user.
  • Rate limit: the GitHub API allows about 60 unauthenticated requests per hour per IP, then answers 403. The debounce helps stay under it, and the 403 branch gives a clear message when it happens.
