event.preventDefault()

Submit Interception

When a form is submitted, the browser's default behavior is to navigate to the action URL or reload the page. event.preventDefault() stops this immediately, letting your JavaScript take full control. This is the first line of every JS form validation handler.

JavaScript 
const form = document.querySelector('#my-form');

form.addEventListener('submit', (e) => {
  e.preventDefault();  // ← STOP the page reload!

  // Now run your own custom validation
  const email = document.querySelector('#email').value;

  if (!email) {
    showError('Email is required');
    return;  // stop here
  }

  // All good — submit programmatically or via fetch()
  console.log('Form is valid! Sending...');
});

Key Points
  • Listen on the 'submit' event of the <form> element, not the button's click event.
  • e.preventDefault() must be called at the very beginning, before any asynchronous code or promises.
  • Without preventDefault(), the browser reloads the page even if you have validation errors below.
  • The event object e also contains e.target — a direct reference to the form element itself.
