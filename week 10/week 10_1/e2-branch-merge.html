Git Branching & Merging

Create a Branch and Merge It

Create an isolated feature branch, implement and commit new changes, switch back to the main branch, and merge the feature branch cleanly into history.

Branch & Merge Command Workflow bash
# 1. Create and switch to a new feature branch
$ git checkout -b feature/landing-page-redesign
Switched to a new branch 'feature/landing-page-redesign'
# 2. Modify files on the feature branch
$ git add index.html catalogue.html recipe-details.html
# 3. Commit the feature changes
$ git commit -m "feat: landing page redesign, catalogue separation, and recipe details"
[feature/landing-page-redesign 4a82b91] feat: landing page redesign... 3 files changed
# 4. Switch back to main branch (files revert to main state)
$ git checkout main
Switched to branch 'main'
# 5. Merge the feature branch into main
$ git merge feature/landing-page-redesign
Updating e5419f7..4a82b91

Branching & Merging Principles

  • ✓ git checkout -b <name> isolates experimental or feature work from the production main branch.
  • ✓ Switching branches with git checkout updates your working directory to match the target branch's snapshot.
  • ✓ git merge <branch> incorporates history and file modifications back into your current checked-out branch.
  • ✓ GitHub Pull Requests allow teams to propose, test, and merge branches into main collaboratively.
